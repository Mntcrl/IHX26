# XRPL Testnet development integration

`galaxy-dev` is a Linux development tool. It uses desktop proving and an Ed25519 credential that **does not have App Attest**. A passing proof and correct image binding therefore produce `UNSUPPORTED`, never `VERIFIED`. The tool refuses other configured networks.

## Run from a real capture

Build the `galaxy-dev` and `galaxy` CLIs with `scripts/with-slot.sh cargo build --release -p galaxy-devtools -p galaxy-cli`. Place the matching GXCB, witness graph, and proving key in `circuits/artifacts/v1m/`, or set `GALAXY_E2E_ARTIFACTS` to an alternate coherent set. The circuit descriptor pins the exact graph and zkey digests.

Run `make integration-test`. The runner uses distinct real GXRW sources from `fixtures/real/calibration/classes/genuine-3d` (or `GALAXY_E2E_SOURCES`), a named Testnet wallet (`GALAXY_E2E_WALLET`), and one device key (`GALAXY_E2E_DEVICE`). Wallet seeds and credential keys are stored under `~/.config/galaxy/wallets/`, with mode 0600. The faucet only accepts a funding request; the runner checks validated balance before publication. It publishes the GXCB chunks and CIRCUIT manifest and the GXDB chunk(s) and DEVICE manifest. The run-local `network.toml` explicitly pins the circuit chosen by the operator; ledger publication alone does not make it trusted.

Each capture profile has its own CAPTURE and PROOF, because JPEG encoding changes the committed raster. The `jpeg-v1` run also exports the decoded JPEG raster as a lossless PNG using the same references. A run locks its CAPTURE to the first validated ledger and derives exactly one challenge at `L0 + 5`. If the reference engine rejects it, `galaxy-dev capture` writes `INCONCLUSIVE` to `run.json`, exits 30, and publishes no PROOF. The runner proceeds to a different GXRW file. A host-local claim binds the source to its private run journal; another run exits 17 rather than generating a fresh challenge for it.

All exports, mutated images, and run journals are stored in mode-0700 directories under `fixtures/real/e2e-development/`. **Never commit them or the raw capture, GXEV, or witness.** Recover an interrupted `galaxy-dev capture` using the same `--run-dir` and parameters (omit `--interrupt-after-capture`). It queries the persisted signed blob by hash, not a freshly signed CAPTURE. `--duplicate-capture` submits the identical blob twice. `--case invalid-proof` and `--case expired-proof` are explicit development experiments: the former submits a canonical but invalid proof; the latter waits past the signed window and expects `tefMAX_LEDGER`. Use separate capture sources; neither experiment is a certification run.

Use `scripts/e2e-transactions.sh <session>` to exercise interruption recovery, duplicate submission, and canonical invalid proof rejection. Add `--expired-proof` to wait until after the full policy proof window before submitting that deliberately expired blob. This uses a separate wallet (`GALAXY_E2E_FAULT_WALLET`). When using historical sessions, set `GALAXY_E2E_ARTIFACTS` to the matching set for that session.

## Verify, record, and test images

- `galaxy --network-config <session>/network.toml --json verify --no-discovery <image>` verifies directly from the embedded references, without a Galaxy node.
- `galaxy-dev --config <session>/network.toml record <image> --output <recording.json>` runs the shared verifier live and records its successful read-only XRPL RPC exchanges. It writes the fixture only if image binding and Groth16 pass and the verdict is unsupported solely for the development credential. `galaxy --network-config <session>/network.toml --recording <recording.json> --json verify --no-discovery <image>` replays these same exchanges offline.
- `scripts/e2e-images.sh <session>` asserts the offline direct verdicts for the originals, lossless PNG of the decoded JPEG, substituted XMP, one-pixel change, crop, resize, and JPEG recompression. It uses Python 3.11+ and Pillow with JPEG XMP support.
- `scripts/e2e-node.sh <session>` builds or uses a real local `galaxy-node`, starts at the first successful session CAPTURE, waits for it to catch up to a validated Testnet tip, and runs the metadata-removal and unregistered-image lookup cases. To use an already-running Testnet node instead, run `scripts/e2e-images.sh <session> <node-url>`; the node must cover the session's CAPTURE and PROOF ledgers without gaps. `NOT_FOUND` means no binding CAPTURE in the consulted ranges, never a claim of global absence. Only the derived photo ID goes to the node.
- The public [`test-vectors/e2e/`](../test-vectors/e2e/) recordings contain XRPL responses only. Run `tests/integration/replay-recorded.sh <network.toml> <recording.json> <CAPTURE_TX>` to check real Testnet Groth16 and ledger binding without the private photo. Historical circuit configurations are scoped to their replay fixtures, not the deployment allowlist.
- `node tests/integration/chromium-replay.mjs <session> <dist> <galaxy-binary>` opens the real browser UI with a dedicated headless Chromium session and compares the reports for the private PNG and JPEG against the native CLI. Build the web app for `<session>/network.toml` (`GALAXY_WEB_NETWORK_CONFIG`), using a private Vite output directory; RPC responses are replayed over loopback and the browser reads the photo locally.
- `scripts/e2e-decentralization.sh <session>` uses three separate node caches and one bootstrap endpoint per node. It tests peer exchange, lookup through each independent index, incorrect/omitting/unavailable peers, a late-starting index, and verification after all test nodes are stopped. It uses the `test-faults` node feature, never a production fault configuration.

Current measured results are in [measurements.md](measurements.md).
