# XRPL Testnet development integration

`galaxy-dev` is a Linux development tool. It uses desktop proving and an Ed25519 credential that **does not have App Attest**. A passing proof and correct image binding therefore produce `UNSUPPORTED`, never `VERIFIED`. The tool refuses other configured networks.

## Run from a real capture

Build current binaries with `CARGO_TARGET_DIR=target/Integration scripts/with-slot.sh cargo build --release -p galaxy-devtools -p galaxy-cli -p galaxy-node`. Place the matching circuit ID, witness graph and proving key in `circuits/artifacts/v1m/`, or set `GALAXY_E2E_ARTIFACTS` to an alternate coherent set. The on-ledger circuit descriptor pins the exact graph and zkey digests.

Run `make integration-test`. The runner selects distinct real GXRW sources from `fixtures/real/calibration/classes/genuine-3d` (or `GALAXY_E2E_SOURCES`), a named Testnet wallet (`GALAXY_E2E_WALLET`), and one device key (`GALAXY_E2E_DEVICE`). Use a new wallet name for a fresh registration; the default is separate from the pre-hardening wallet. Wallet seeds and credential keys live under `~/.config/galaxy/wallets/` with mode 0600. The faucet only accepts a funding request; the runner checks the validated balance before publication.

The runner uses the CIRCUIT manifest already pinned in `deployments/networks/xrpl-testnet.toml` (or `GALAXY_E2E_CONFIG`); it does not republish the circuit or widen the allowlist. To use a different circuit, first register its GXCB using `galaxy-dev register-circuit`, then explicitly review and pin its IDs and registration hash in a separate Testnet config. For a fresh device account, `register-dev-device` submits and validates the memo-free AccountSet `SetFlag: 5` before publishing the GXDB chunks and DEVICE manifest. The first record signs the zero `AccountTxnID` sentinel, and later records sign the previous own-success hash. The development wallet is locked and its signed transactions are validated serially.

Each capture profile has its own CAPTURE and PROOF, because JPEG encoding changes the committed raster. The `jpeg-v1` run also exports the decoded JPEG raster as a lossless PNG using the same references. A run locks its CAPTURE to the first validated ledger and derives exactly one challenge at `L0 + 5`. If the reference engine rejects it, `galaxy-dev capture` writes `INCONCLUSIVE` to `run.json`, exits 30, and publishes no PROOF. The runner proceeds to a different GXRW file. A host-local claim binds the source to its private run journal; another run exits 17 rather than generating a fresh challenge for it.

All exports, mutated images, and run journals are stored in mode-0700 directories under `fixtures/real/e2e-development/`. **Never commit them or the raw capture, GXEV, or witness.** Recover an interrupted `galaxy-dev capture` using the same `--run-dir` and parameters (omit `--interrupt-after-capture`). It queries the persisted signed blob by hash, not a freshly signed CAPTURE. `--duplicate-capture` submits the identical blob twice. `--case invalid-proof` and `--case expired-proof` are explicit development experiments: the former submits a canonical but invalid proof; the latter waits past the signed window and expects `tefMAX_LEDGER`. Use separate capture sources; neither experiment is a certification run.

Use `scripts/e2e-transactions.sh <session>` to exercise interruption recovery, duplicate submission, and canonical invalid proof rejection. Add `--expired-proof` to wait until after the full policy proof window before submitting that deliberately expired blob. This uses a separate wallet (`GALAXY_E2E_FAULT_WALLET`). When using historical sessions, set `GALAXY_E2E_ARTIFACTS` to the matching set for that session.

## Verify, record, and test images

- `galaxy --network-config <session>/network.toml --json verify --no-discovery <image>` verifies directly from the embedded references, without a Galaxy node.
- `galaxy-dev --config <session>/network.toml record <image> --output <recording.json>` records read-only XRPL exchanges from a single endpoint for one verification. It writes the fixture only if image binding, both transaction-chain checks, complete history and Groth16 pass and the verdict is unsupported solely for the development credential. `galaxy --network-config <session>/network.toml --recording <recording.json> --json verify --no-discovery <image>` replays the same exchanges offline.
- `scripts/e2e-images.sh <session>` checks the offline direct verdicts for originals, lossless PNG of the decoded JPEG, substituted XMP, one-pixel change, crop, resize and JPEG recompression. It also checks manual CAPTURE/PROOF references for both profiles after removing metadata. It uses Python 3.11+ and Pillow with JPEG XMP support.
- `scripts/e2e-node.sh <session>` starts a real local `galaxy-node` at the first successful session CAPTURE, waits for it to catch up to a validated Testnet tip, and tests live `--lookup` for both profiles and for an unregistered image. To use an already-running Testnet node, run `scripts/e2e-images.sh <session> <node-url>` instead; the node must cover the session's CAPTURE and PROOF ledgers without gaps. Only the derived photo ID goes to the node. `NOT_FOUND` means no binding CAPTURE in the consulted ranges, never a claim of global absence.
- Public [`test-vectors/e2e/`](../test-vectors/e2e/) recordings contain XRPL responses only. Run `tests/integration/replay-recorded.sh <network.toml> <recording.json> <CAPTURE_TX> [HISTORY_PAGES]` to check real Testnet Groth16 and ledger binding without the private photo. Historical recordings made before AccountTxnID hardening do not satisfy the hardened verifier.
- `node tests/integration/chromium-replay.mjs <session> <dist> <galaxy-binary>` opens the real browser UI with a dedicated headless Chromium session and compares reports for the private PNG and JPEG against the native CLI. Build the web app for `<session>/network.toml` (`GALAXY_WEB_NETWORK_CONFIG`), with a private Vite output directory; RPC responses are replayed over loopback and the browser reads the photo locally.
- `scripts/e2e-decentralization.sh <session>` uses three separate node caches and one bootstrap endpoint per node. It tests peer exchange, lookup through each independent index, incorrect/omitting/unavailable peers, a late-starting index, and verification after all test nodes are stopped. It uses the `test-faults` node feature, never a production fault configuration.

## Replay the own-transaction history fallback

Install the pinned XRPL JavaScript SDK with `npm --prefix scripts/xrpl-vectors ci`. Create and fund a separate Testnet wallet via `galaxy-dev --wallet <name> wallet new` and `wallet fund`, then check its validated balance. With both captures complete and neither wallet used by another process, run `scripts/e2e-history.sh <session> <name>`. It validates 201 one-drop Testnet Payments from the second wallet to the registration account, checks that the registration's `AccountTxnID` stayed unchanged, and verifies the JPEG with `--history-pages 1`. Run the same command after an interruption to recover payments already validated since the JPEG PROOF. The runner requires a real pagination marker and a successful AccountTxnID walk, not just the expected verdict. A second verification with `--history-pages 0` forces the walk for comparison. Both sets of public RPC exchanges can be replayed offline with their original budgets.
