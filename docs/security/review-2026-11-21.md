## What I checked and found sound (verified controls)

**Groth16 (galaxy-crypto)**
- Every decoder rejects non-canonical coordinates, points off the curve, points outside the subgroup (G1 and G2), the point at infinity, wrong lengths and trailing bytes (`groth16.rs:134,218-243`).
- `verify` requires exactly as many public inputs as the key declares (`:201-205`).
- The verifier pins 22 public inputs and the layout `galaxy-pc-v1-public-22` (`circuit.rs:105-119`).

**Public inputs**
- All 22 are rebuilt only from ledger data: `rgb_root`, `evidence_root` and `capture_id` from the signed core; the seed from network, `capture_id`, Lsel and the Lsel header hash; tiles from the seed (`pipeline.rs:575-589`, `public.rs`).
- The PROOF memo's selection index, selection hash, circuit and network must all match (`:791`).
- The PROOF window is Lsel < Lproof ≤ deadline (`:784`).
- The PROOF must come from the CAPTURE account; the first valid one in ledger order wins; an advertised proof cannot select itself (`:840-846`).

**Verifying-key trust**
- Taken only from the configured allowlist entry: circuit id, policy id and VK digest are checked against the descriptor, policy and VK bytes, with the policy validated (`circuit.rs:38-47,92-125`).
- The CAPTURE's policy must equal the configured one (`circuit.rs:43`).

**Replay and binding**
- Transaction blobs must hash to the requested hash (`pipeline.rs:426-428`).
- The DEVICE record must come before the CAPTURE and use the same account (`:611-616`).
- The registration ledger hash must match (`:618`).
- Lpre window and hash checks (`:557-563`).
- Duplicate `capture_id`, counters, and revocations with a backdating range (`:686-725`).
- The registration window is reg ≤ manifest ≤ reg + 100, and chunks must come before the manifest from the same account (`registry.rs:192-193,240-243`).
- Mainnet is refused unless explicitly enabled.
- A dev-unattested credential can never reach `VERIFIED` (`pipeline.rs:378`).

**Circuit**
- Only two witness-only assignments (`<--`) exist (`geometry/gadgets.circom:197,216`). Both have matching constraints: `r = num − q·den`, a signed range on `q`, and `r` and `den−1−r` each confined to dBits, with qBits + dBits < 249 (no field wrap).
- Merkle position bits come from `Num2Bits`, `Num2Bits_strict`, constants, or `GalaxyFramePosition` (with `by < 48`). Leaf and node hashes bind the position, kind, frame and level (`merkle.circom`, `leaf.circom:55`).
- Every mux selector is shown to be 0/1: `posBits`, the `(tmp−1)(tmp−2)=0` check, `starBits`, and the GeoPlane selectors.
- All comparisons (`GeoLT` via `Num2Bits(n+1)`, n < 249) are on values with proven bounds: bytes 8-bit, depth 16-bit, confidence 2-bit, camera 26/32/48-bit, IMU 32-bit.
- All five pass flags are built from 0/1 gadgets, so `PASS === 1` is sound (`main_v1m.circom:138-142`).
- Every public input is constrained and used.
- The `inspect.log` warnings are unused bits and outputs only: CA01 on `GeoPlaneSupport.points` is the depth value, which reaches the support check through `maskedD`.

**App Attest**
- Root fingerprint pinned (`certificate.rs:48`); chain and validity checked at the manifest ledger close time converted to Unix time (`ledger.rs:344`).
- Certificate profile and signature algorithms checked; nonce extension decoded as exact DER.
- `key_id`, `credentialId` and COSE key all checked; RP ID hash, AAGUID per environment, attestation counter 0 (`apple.rs:86-128`).
- Assertion: ES256 over the nonce (`:171`), counter > 0; strictly increasing per registration (`lib.rs:304-319`).

**Untrusted input**
- Wire decoders check version, lengths, canonical scalars and trailing bytes (`wire.rs:483-545`).
- XRPL codec has depth, size and item limits (`codec.rs:24-28`).
- Image decoding: PNG walks all chunks before inflating, with an exact output size; JPEG has a strict layout and a 1024×768 cap; 16 MiB overall cap (`lib.rs:54`).
- XMP rejects DOCTYPE.
- GXRW region offsets use checked arithmetic and must tile the payload exactly (`ingest.rs:157-182`).

**Discovery boundary**
- Node hints are only hints; hints that do not match the image are discarded (`pipeline.rs:241-246`).
- SSRF guard: IP literals checked plus DNS-time checks, no redirects, no proxy, 4 s timeouts, 256 KiB body cap (`client.rs`).
- Web: consent gate, CSP `connect-src`, `redirect:'error'`, size caps, no `innerHTML`.
- Node SQL uses static filters with parameters only (`db.rs:361-370`).

**Secrets and privacy**
- Wallet seed in the Keychain, `WhenUnlockedThisDeviceOnly`, not synchronized (`WalletSeedStore.swift:22,29`).
- Files written with `.completeFileProtection` and excluded from backup.
- Bluetooth: identifiers are HMAC'd with a per-session key, the key is rotated and observations cleared; no background modes.
- Salts come from the OS RNG, 248-bit; the prover uses random r and s.
- Development wallet files are 0600, loaded with errors that do not echo contents; my search for secrets in log statements found nothing; `fixtures/real/` and `circuits/build/` are gitignored.

## Corrections to `threat-model.md` (claim → evidence → corrected text)

1. **"Ledger sampling … no retries"** (line 41) → S-02 evidence (`pipeline.rs:697-703,261`; `capture.rs:174-187`). Corrected text: "One challenge per CAPTURE (Lsel = L0 + `sel_offset`). The protocol does not limit how many CAPTUREs a credential holder publishes for the same photo or evidence, and lookup keeps the best one: per-challenge false-accept rates are per attempt. Re-challenges are limited only by App Attest (production app behaviour); a near-identical pixel variant gets a new challenge."

2. **"Malicious RPC … multiple endpoints configurable … mitigated by … several independent endpoints"** (line 43) → `native.rs:49,136-154`, `ledger.ts:106-119`. Corrected text: "Several endpoints are tried in order as failover; answers are not cross-checked, and one verification may combine answers from different endpoints. Transaction signatures are not verified: `account_tx` entries (history, chunks) are trusted RPC claims. Only a locally operated rippled removes the remote trust."

3. **"Tx hash recomputed from the returned blob (content integrity)"** (row 1 and line 43) → `ledger.rs:223`, `transaction.rs:124-125`. Corrected text: "Transactions fetched by hash (CAPTURE, DEVICE/CIRCUIT manifest, exact PROOF) are bound to that hash. Records found through `account_tx` (counters, duplicates, REVOKE, PROOF candidates, bundle chunks) are bound only to the RPC's answer."

4. **"Unavailable historical data: UNAVAILABLE state"** (line 47) → S-01 (`pipeline.rs:27-28,672-750`). Add the threat: "Third-party history inflation: any account can send transactions to a registration account; above 12,800 transactions in [manifest ledger, latest] every capture of that registration becomes UNAVAILABLE, permanently." Residual: "open until the scan is narrowed and revocation is redesigned."

5. **"Range checks on every private input"** (line 38) → `commitment.circom:40-46` range-checks only the salts; `bluetooth`, `noise`, `meta`, `roots` and Merkle siblings have none (`main_v1m.circom:15-35`). Corrected text: "Every private value read by a policy predicate is range-bound (leaf bytes 8/16/2 bit, camera 26/32/48 bit, IMU 32 bit, positions 6 bit); committed-only aggregates and Merkle siblings are opaque field elements bound by Poseidon."

6. **"Strict bounded decoders … fuzz-style tests"** (line 46) → my search for fuzz/property tests found nothing. Corrected text: "Strict bounded decoders with example-based negative tests; no fuzzing or property tests yet."

7. **"Groth16 setup … Production requires a multi-party phase-2 ceremony"** (line 40) → `circuit.rs:110` only requires the `ceremony` field to be non-empty; acceptance comes purely from the config. Corrected text: "The verifier does not enforce a ceremony class: it reports `proof.ceremony`; trusting a `development-single-party` key is a config decision. The shipped Testnet config has no accepted circuit (`xrpl-testnet.toml:37`), and the registered CIRCUIT `1C83F97F…` binds policy `ef744a7f…`, not the current `4ad25185…`."

8. **Privacy: "nodes learn photo_ids only after explicit consent"** (§4) → `galaxy-cli/main.rs:67,306-308`. Corrected text: "Web: only after the consent checkbox. CLI: whenever nodes are configured (`--node` or `GALAXY_NODES`) and the image has no Galaxy XMP, the photo ID is sent automatically" (until S-06 is fixed).

9. **Privacy: "XRPL endpoints learn which transaction hashes are queried"** (§4) → `ledger.rs` `account_tx`/`ledger` calls. Corrected text: "XRPL endpoints learn the queried transaction hashes, the photographer's account (`account_tx`) and the ledger indexes; they can link lookups to captures."

10. **Apple App Attest row: "development and production environments are distinct classes"** → `xrpl-testnet.toml:29`; `test-vectors/attestation/README.md:7`. Add: "Development-environment credentials come from debuggable builds signed by the team (including free teams); they attest the app identity, not its integrity. Production configs should accept `production` only."
